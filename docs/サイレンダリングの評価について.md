# Blazor の再描画、どこまで走るの？

## はじめに

Blazor のコンポーネント再描画の仕組みがよくわかってなかったのでログります。

## 知ったこと

`@onclick` などの `@on` ディレクティブでメソッドを呼び出したとき、**そのイベントを持つ要素だけでなく、コンポーネント全体が再描画の評価対象になる。**

MS Docs にもこう書いてある。

> イベントが通知され、その独自のイベント ハンドラーの 1 つを呼び出した後。

「イベントハンドラを呼び出した後」は要素単位ではなくコンポーネント単位のトリガー。

## 実例

これを確認したきっかけがこのコード。

```razor
@* Counter.razor *@
<button class="btn btn-primary" @onclick="Increment">加算</button>

@code {
  public int Count { get; set; } = 0;

  private void Increment()
  {
    Count++;
  }
}
```

```razor
@* Rendering.razor *@
@page "/rendering"

<Counter @ref="counter1" />
<p>カウント: @counter1?.Count</p>

<button class="btn btn-secondary" @onclick="HandleClick">確認</button>
<p>@message</p>

@code {
  private Counter? counter1;
  private string message = "";

  private void HandleClick()
  {
    message = "ボタンを押した";
  }
}
```

「加算」を何度押しても `カウント:` の表示は変わらない。でも「確認」を押すと最新の値になる。

理由はこう。

```
「確認」ボタンを押す
  ↓
親のイベントハンドラ（HandleClick）が走る
  ↓
親コンポーネント全体の再描画評価がトリガーされる
  ↓
@ref のインスタンスから Count が読み直される
  ↓
表示が最新になる
```

`HandleClick` は `message` しか変えていないのに、`@counter1?.Count` も一緒に評価されるのがポイント。


## この例はちょっと特殊

ただこの挙動は `@ref` を使って子の状態を親で表示しているという特殊な構成が原因でもある。

通常、子の状態を親に反映したい場合は `EventCallback` を使って子から親に通知する設計にする。`@bind` を使えば子の状態が変わるたびに即時更新される。

```razor
@* @bind を使った場合 *@
<Counter @bind-Count="count1" />
<p>カウント: @count1</p>
```

`@ref` で子の値を読もうとしたのがそもそも素直でない設計だった、という話でもある。

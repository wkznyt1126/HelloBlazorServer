# @on のイベントハンドラはコンポーネント全体の再描画をトリガーする

## はじめに

Blazor で `@ref` を使って子コンポーネントのインスタンスから値を取得し、
画面に表示しようとしたとき、こんな現象に遭遇した。

- DropDownList で項目を選択しても、`@ref` 経由で表示している選択インデックスが更新されない
- 関係ないボタンを押したら、そのタイミングで表示が最新になった

なぜこうなるのか。

---

## 構成

DropDownList コンポーネントを親から使う構成。

```razor
@* DropDownList.razor *@
<select @onchange="HandleChange">
    @foreach (var item in Items)
    {
        <option value="@item">@item</option>
    }
</select>

@code {
    [Parameter]
    public IEnumerable<string> Items { get; set; } = [];
    [Parameter]
    public int? SelectedIndex { get; set; }

    private void HandleChange(ChangeEventArgs e)
    {
        SelectedIndex = int.Parse(e.Value?.ToString() ?? "0");
    }
}
```

```razor
@* Rendering.razor *@
@page "/rendering"
<PageTitle>レンダリング動作確認</PageTitle>

<DropDownList
    @ref="dropDownList1"
    Items="@items1"
    SelectedIndex="@SelectedIndex1"
/>
<p>選択中: @dropDownList1?.SelectedIndex</p>  @* @ref のインスタンスから取得 *@

<button @onclick="HandleClick">更新確認</button>
<p>@message</p>

@code {
    private DropDownList? dropDownList1;
    private List<string> items1 = ["Apple", "Banana", "Cherry"];
    private int SelectedIndex1 = 0;
    private string message = "クリック回数：";
    private int clickedCounter = 0;

    private void HandleClick()
    {
        message += clickedCounter.ToString();
    }
}
```

---

## 何が起きているか

DropDownList で項目を選択しても「選択中: 」の表示が変わらない。
しかしボタンを押すと表示が最新になる。

```
DropDownList で項目を選択
  ↓
DropDownList の内部で SelectedIndex が更新される
  ↓
親（Rendering.razor）の再描画はトリガーされない
  ↓
@ref 経由の表示は古いまま  ← ここで止まる
```

```
関係ないボタンを押す
  ↓
親のイベントハンドラ（HandleClick）が走る
  ↓
親コンポーネント全体の再描画評価がトリガーされる  ← ここがポイント
  ↓
@ref のインスタンスから SelectedIndex が読み直される
  ↓
表示が最新になる
```

---

## なぜボタンを押すと更新されるのか

MS Docs によると、`ComponentBase` には次のタイミングで再描画をトリガーするロジックが含まれている。

> イベントが通知され、その独自のイベント ハンドラーの 1 つを呼び出した後。

`@onclick` でハンドラが呼ばれると、**そのコンポーネント全体**の再描画評価が走る。
`HandleClick` は `message` しか変えていないが、`@dropDownList1?.SelectedIndex` も
一緒に評価され、`@ref` のインスタンスから最新値が読み直される。

これが「ボタンを押したら表示が更新された」の正体。

---

## まとめ

- `@on` のイベントハンドラが走ると、**そのコンポーネント全体**の再描画評価がトリガーされる
- 特定の要素だけが再描画されるわけではない
- `@ref` 経由で子の状態を表示している場合、**親の再描画が走るタイミングまで表示は更新されない**

`@ref` で子の状態を親に反映したい場合は、`EventCallback` で親に通知する設計にした方が素直に動く。

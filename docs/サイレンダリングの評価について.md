# Blazor の再描画、どこまで走るの？

## はじめに

Blazor のコンポーネント再描画の仕組みがよくわかってなかったのでログります。

## 学んだこと

学んだことは、`@onclick` などの `@on` ディレクティブでメソッドを呼び出したとき、**そのイベントを持つ要素だけでなく、コンポーネント全体が再描画の評価対象になる。**ということです。

[ASP.NET Core Razor コンポーネントのレンダリング - MS Learn](https://learn.microsoft.com/ja-jp/aspnet/core/blazor/components/rendering?view=aspnetcore-10.0)にもこう書いてあありました。

> Razor コンポーネントは ComponentBase 基底クラスから継承されます。これには次のタイミングで再レンダリングをトリガーするロジックが含まれています。
> * イベントが通知され、その独自のイベントハンドラーの1つを呼び出した後。

## 実例

例として、@ref を使って子コンポーネントの値を親で表示する構成を作りました。
2つのコンポーネントで構成されています。
Counter.razor は加算ボタンを持つ子コンポーネントです。
ボタンを押すと内部の Count が増えますが、親には何も通知しません。
画面側では @ref でこの Counter のインスタンスを参照し、@counter1?.Count で値を表示しています。

```Counter.razor
<button class="btn btn-primary" @onclick="Increment">加算</button>

@code {
  public int Count { get; set; } = 0;

  private void Increment()
  {
    Count++;
  }
}
```

```画面.razor
@page "/rendering"

<Counter @ref="counter1" />
<p>カウント: @counter1?.Count</p>

<button class="btn btn-secondary" @onclick="HandleClick">確認</button>
<p>@message</p>

@code {
  private Counter? counter1;
  private string message = "";

  private void HandleClick()
  {
    message = "ボタンを押した";
  }
}
```

「加算」ボタンを何度押しても `カウント:` の表示は変わりません。
「確認」ボタンから `@on` ディレクティブでメソッドを押すと最新の値になります。

理由はこうです。
`HandleClick` は `message` しか変えていないのに、`@counter1?.Count` も一緒に評価されます。

```
「確認」ボタンを押す
  ↓
親のイベントハンドラ（HandleClick）が走る
  ↓
親コンポーネント全体の再描画評価がトリガーされる
  ↓
@ref のインスタンスから Count が読み直される
  ↓
表示が最新になる
```

## この例はちょっと特殊

ただこの挙動は `@ref` を使って子の状態を親で表示しているという特殊な構成が原因です。
通常、子の状態を親に反映したい場合は `EventCallback` を使って子から親に通知する設計にします。
`@bind` を使えば子の状態が変わるたびに即時更新される。

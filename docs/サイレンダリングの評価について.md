# @on のイベントハンドラはコンポーネント全体の再描画をトリガーする

## はじめに

Blazor で `@ref` を使って子コンポーネントのインスタンスから値を取得し、
画面に表示しようとしたとき、こんな現象に遭遇した。

- 子コンポーネントのボタンを押して内部状態を更新しても、`@ref` 経由で表示している値が更新されない
- 関係ないボタンを押したら、そのタイミングで表示が最新になった

なぜこうなるのか。

---

## 構成

カウンターコンポーネントを親から使う構成。

```razor
@* Counter.razor *@
<button class="btn btn-primary" @onclick="Increment">加算</button>

@code {
    public int Count { get; set; } = 0;

    private void Increment()
    {
        Count++;
    }
}
```

```razor
@* Rendering.razor *@
@page "/rendering"

<Counter @ref="counter1" />
<p>カウント: @counter1?.Count</p>  @* @ref のインスタンスから取得 *@

<button class="btn btn-secondary" @onclick="HandleClick">確認</button>
<p>@message</p>

@code {
    private Counter? counter1;
    private string message = "";

    private void HandleClick()
    {
        message = "ボタンを押した";
    }
}
```

---

## 何が起きているか

「加算」ボタンを押しても `カウント:` の表示が変わらない。
しかし「確認」ボタンを押すと表示が最新になる。

```
「加算」ボタンを押す
  ↓
Counter の内部で Count が増える
  ↓
親（Rendering.razor）の再描画はトリガーされない
  ↓
@ref 経由の表示は古いまま  ← ここで止まる
```

```
「確認」ボタンを押す
  ↓
親のイベントハンドラ（HandleClick）が走る
  ↓
親コンポーネント全体の再描画評価がトリガーされる  ← ここがポイント
  ↓
@ref のインスタンスから Count が読み直される
  ↓
表示が最新になる
```

---

## なぜ「確認」ボタンを押すと更新されるのか

MS Docs によると、`ComponentBase` には次のタイミングで再描画をトリガーするロジックが含まれている。

> イベントが通知され、その独自のイベント ハンドラーの 1 つを呼び出した後。

`@onclick` でハンドラが呼ばれると、**そのコンポーネント全体**の再描画評価が走る。
`HandleClick` は `message` しか変えていないが、`@counter1?.Count` も
一緒に評価され、`@ref` のインスタンスから最新値が読み直される。

これが「確認ボタンを押したら表示が更新された」の正体。

---

## 解決策：即時更新したいなら `@bind` を使う

`@ref` 経由ではなく `@bind` を使えば、子の状態が変わるたびに親へ通知が飛んで即時更新される。

```razor
@* Counter.razor *@
<button class="btn btn-primary" @onclick="Increment">加算</button>

@code {
    [Parameter]
    public int Count { get; set; } = 0;

    [Parameter]
    public EventCallback<int> CountChanged { get; set; }

    private async Task Increment()
    {
        Count++;
        await CountChanged.InvokeAsync(Count);
    }
}
```

```razor
@* Rendering.razor *@
<Counter @bind-Count="count1" />
<p>カウント: @count1</p>

@code {
    private int count1 = 0;
}
```

| 方法 | 更新タイミング |
|---|---|
| `@ref` | 親の再描画が走るまで古いまま |
| `@bind` | 子から `EventCallback` で通知されるので即時更新 |

---

## まとめ

- `@on` のイベントハンドラが走ると、**そのコンポーネント全体**の再描画評価がトリガーされる
- 特定の要素だけが再描画されるわけではない
- `@ref` 経由で子の状態を表示している場合、**親の再描画が走るタイミングまで表示は更新されない**
